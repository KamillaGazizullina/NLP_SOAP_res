# Дизайн-документ: NLP-генератор медицинских SOAP-протоколов

## 1. Контекст проекта

### 1.1 Бизнес-задача
**Проблема:** Врачи-терапевты тратят до 40% времени приёма на заполнение медицинской документации. Это снижает качество внимания к пациенту и ведёт к выгоранию персонала.
**Решение:** NLP-сервис, который принимает на вход текст диалога врача и пациента и преобразует его в структурированный медицинский протокол по стандарту SOAP (Subjective, Objective, Assessment, Plan).

**Критерии успеха:**
1. Корректное распределение фактов по разделам (жалобы — в S, осмотр — в O).
2. Отсутствие «галлюцинаций» (модель не должна придумывать симптомы).
3. Использование правильной медицинской терминологии.

### 1.2 Целевая аудитория
Терапевты, врачи телемедицинских сервисов.

### 1.3 Ограничения и допущения
- Работа только с текстом (обработка аудио не входит в рамки проекта).
- Допущение: входной текст содержит достаточно информации для заполнения минимум 3-х разделов SOAP.

## 2. Архитектура решения

### 2.1 Общая схема
`Text Input (Dialog) -> Preprocessing -> LLM (Summarizer/Extractor) -> Post-processing -> SOAP Note`

### 2.2 Технологический стек
- **Core:** LLM (Llama 3 / Qwen / Saiga), Few-shot промптинг.
- **Backend:** FastAPI.
- **Frontend:** Streamlit.
- **Infrastructure:** Docker & Docker Compose.

### 2.3 Безопасность
Локальный запуск модели (Ollama) гарантирует, что медицинские данные не передаются на сторонние сервера.

## 3. Данные и качество

### 3.1 Сбор данных
Использование транскриптов из датасетов ACI-BENCH и MediQA-Chat, а также 20–30 вручную подготовленных диалогов на русском языке для тестирования.

### 3.2 Метрики качества
- **ROUGE-L:** сравнение с эталонным отчетом.
- **Entity Coverage:** % извлеченных симптомов из исходного текста.

## 4. Модель и генерация
Использование модели **Qwen 2.5 (3B/7B)** или **Saiga Llama 3**. 
Техника **Few-shot Prompting** для обеспечения стабильного формата JSON (S, O, A, P).

## 5. UX / Пользовательский опыт
Сценарий: врач вставляет текст диалога в веб-интерфейс, получает структурированную заметку в четырех блоках с возможностью копирования и скачивания в .txt.

## 6. План внедрения
1. **Фаза 1:** Сбор и перевод тестовых диалогов.
2. **Фаза 2:** Настройка промптов и логики парсинга.
3. **Фаза 3:** Создание интерфейса на Streamlit.
4. **Фаза 4:** Тестирование и оценка метрик.

## 7. Риски и смягчение
- **Риск:** Спутанность ролей «Врач/Пациент». 
- **Смягчение:** Четкое разделение ролей в промпте.
- **Риск:** Галлюцинации. 
- **Смягчение:** Инструкция «Пиши только то, что есть в тексте. Если данных нет — ставь прочерк».
